# 🐙 GitHub MCP Agent

A Streamlit application that lets you ask natural-language questions about GitHub repositories. It uses a Groq-powered language model, LangGraph, and GitHub's official remote Model Context Protocol (MCP) server to retrieve repository information.

## Features

- Load any public or private GitHub repository you have access to.
- Enter a repository using `owner/repo` or a GitHub URL.
- Ask questions such as “What does this repository do?” or “Explain the README.”
- Use MCP tools to retrieve actual repository information.
- Keep model requests stateless to reduce unnecessary token usage.
- Filter available MCP tools using an allowlist.
- View tool calls and execution details in the State Logs panel.
- Run the MCP client independently to inspect available tools.

## Requirements

Before starting, make sure you have:

- Python 3.10 or newer
- A Groq API key
- A GitHub Personal Access Token

## Installation

Open your terminal in the project directory and install the required packages:

```bash
python -m pip install streamlit python-dotenv langchain-core langgraph langchain-mcp-adapters langchain-groq
```

Alternatively, if `requirements.txt` already exists:

```bash
python -m pip install -r requirements.txt
```

## Environment Setup

Create a `.env` file in the root directory of your project.

Add your credentials:

```env
GITHUB_PERSONAL_ACCESS_TOKEN=your_github_personal_access_token
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=your_supported_groq_model
```

Get your Groq API key from [Groq Console](https://console.groq.com/keys).

Create a GitHub Personal Access Token from [GitHub Settings](https://github.com/settings/personal-access-tokens/new).

Give the token only the repository permissions required for your application. Read-only permissions are recommended for a read-focused agent.

Check the [Groq model documentation](https://console.groq.com/docs/models) to select a model currently available to your account.

**Security:** Never commit your `.env` file or expose API keys in public repositories.

Add the following entries to `.gitignore`:

```gitignore
.env
.venv/
venv/
__pycache__/
*.py[cod]
.streamlit/secrets.toml
```

## Running the Application

Start the application using:

```bash
python -m streamlit run app.py
```

Open the local URL displayed in your terminal. Usually:

`http://localhost:8501`

### How to Use

1. Enter a GitHub repository in the sidebar, for example `github/github-mcp-server`.
2. Click **Load Repository**.
3. Type a question in the chat input.
4. Review the answer generated by the agent.
5. Expand **State Logs** to inspect MCP tool calls and execution details.

## Testing the MCP Connection

Before debugging the Streamlit interface, test the MCP connection independently:

```bash
python mcp_client.py
```

This should display the tools exposed by the GitHub MCP server and identify which tools are permitted by the configured allowlist.

If the connection fails, verify your GitHub token, network connection, MCP configuration, and installed package versions.

## Tool Allowlist

The agent should load only the tools configured in `GITHUB_TOOLS_ALLOWLIST` in `mcp_client.py`.

Start with the read-only `get_file_contents` tool. Add more tools only when required, while considering provider rate limits and token usage.

Write-capable tools, such as those that create issues, fork repositories, edit files, or open pull requests, should remain disabled unless explicitly needed and protected by appropriate safeguards.

## Architecture Overview

The application follows this workflow:

1. The user enters a GitHub repository and asks a question.
2. Streamlit passes the repository and current question to the LangGraph agent.
3. The Groq language model determines whether a permitted MCP tool is needed.
4. If necessary, the MCP client calls GitHub's remote MCP server.
5. The tool result is returned to the model.
6. The model generates an answer based on the available information.
7. Streamlit displays the answer and relevant state logs.

The model is stateless between questions: previous chat messages can remain visible in the interface without being sent to the model in subsequent requests.

For more details, see `architecture.md` if it is included in your project.

## Troubleshooting

### Missing API Keys

Make sure `.env` exists in the project root and contains the required credentials. Restart Streamlit after updating environment variables.

### Groq Model Errors

Check that your configured model ID is currently supported by your Groq account. Handle rate limits by waiting before retrying and avoiding unnecessary tool calls.

### MCP Connection Errors

Run `python mcp_client.py` separately. Check your GitHub token, configured MCP endpoint, transport, and package compatibility.

### Application Stuck on "Thinking..."

Check the terminal and State Logs for request start, tool execution, model response, and completion timestamps.

Make sure exceptions are displayed clearly and loading indicators stop when requests succeed or fail.

### Import Errors

Install the required dependencies and verify that module names in your imports match your actual filenames.

```bash
python -m pip install -r requirements.txt
```

## Deployment

The application can be deployed to [Streamlit Community Cloud](https://share.streamlit.io/), provided the MCP connection and its runtime dependencies work in the hosted environment.

1. Push your project to GitHub.
2. Make sure `.env` is excluded from version control.
3. Ensure `requirements.txt` lists the required dependencies.
4. Sign in to Streamlit Community Cloud with GitHub.
5. Create a new app and select `app.py` as the entry point.
6. Configure your GitHub token, Groq API key, and other required environment variables in the app's secrets settings.
7. Deploy and test the hosted application.

Remember that a project working locally on Windows may require additional configuration to run on the cloud's Linux environment.
